# ChatPulse 模拟电脑：各 App 功能与商业产品界面研究

日期：2026-10-02。范围是当前桌面可打开的 8 个业务 App，以及图片、回收站、文件夹、文本文档四类系统窗口。功能以当前源码和 `docs/features/` 为准；界面判断来自 1440×900 的 Playwright 无头截图，测试数据与用户数据隔离。外部资料通过 HTTP 访问官方产品或官方文档核对，以下借鉴的是信息组织方式，不是照搬视觉素材。

## 先看见的问题

1. **工作区过小。** 业务 App 默认浮动窗口约 1037×725，模拟浏览器标题栏和地址栏又占约 90 像素。设置、日志、商业街和小屋在首屏都显得拥挤；场景下半部尤其容易被截断。
2. **视觉层级不稳定。** 各 App 分别定义字号、颜色、圆角、阴影和操作栏。主操作有时与维护功能并列，表单/状态/说明同时抢占注意力。
3. **文本可读性差。** 社交页粉蓝文字叠在浅粉背景上尤其明显；其他页面有大量 11–12px 的标签、状态和说明。需要按 WCAG 2.2 对普通文本、控件焦点和目标尺寸逐屏检查。
4. **导航重复或语义不清。** MCP 同时有顶部栏目和左侧图标导航；设置有左栏、角色子栏目、右侧信息栏；记忆页的视图切换与维护入口权重接近。用户需要先判断“我在哪”才能执行任务。
5. **空状态消耗大面积却没有下一步。** 社交首屏、日志、MCP、图片和回收站的空状态应解释原因并给出最相关的操作。

## 每个 App 的功能、参考与改版方向

| App | 现在实际承担的功能 | 参考的成熟产品模式 | 具体界面方向 |
| --- | --- | --- | --- |
| **社交** | 联系人、私聊、群聊、消息搜索、回复版本、语音、转账/红包、角色日记与 RAG 状态。入口在 `features/characters`、`private-chat`、`group-chat`。 | [Discord 新手指南](https://support.discord.com/hc/en-us/articles/360045138571-Beginner-s-Guide-to-Discord) 的会话/频道分区与稳定聊天工作区。 | 左侧只放会话列表和搜索；中间让消息成为主角；右侧角色资料、日记等按需展开。首屏空聊天给“选择会话/创建角色”操作。消息、输入框和状态文本使用深色高对比；RAG 的详细阶段放进可展开状态，而非横贯聊天的常驻流程条。 |
| **记忆库** | 记忆地图、人物/主题筛选、检索、详情、来源追溯、编辑、外部导入和维护任务。 | [Obsidian Search](https://help.obsidian.md/plugins/search) 与 [Graph view](https://help.obsidian.md/plugins/graph) 对搜索结果、关系图和筛选的分工；[Notion](https://www.notion.com/product) 的资料工作区。 | 主导航改成“浏览记忆 / 维护 / 导入”，图谱与列表是浏览页内部视图。保持人物筛选和搜索可见；点击节点后在右侧查看来源与编辑。健康指标集中为一条概览，不用五张同权重卡片压缩结果区。 |
| **MCP 实验室** | 网页搜索、抓取 URL、外部知识资料、搜索源/密钥设置、任务轨迹与上下文检查。 | [Postman 导航文档](https://learning.postman.com/docs/getting-started/basics/navigating-postman/) 的任务工作区和结果检查；[VS Code 用户界面](https://code.visualstudio.com/docs/getstarted/userinterface) 的活动栏、主编辑区、次级面板。 | 保留一种主导航：左侧带文字的栏目，去掉重复的顶部四按钮。中间按“输入→运行→结果”组织，右侧检查器可收起；空结果提示示例查询。密钥设置放在“设置”，不要与搜索任务同级露出。 |
| **设置** | 个人资料、账号与会话安全、角色人设、模型、行为、声音、角色数据和整库备份。 | [Windows NavigationView](https://learn.microsoft.com/en-us/windows/apps/design/controls/navigationview) 的自适应顶层导航与 [Fluent 2](https://fluent2.microsoft.design/) 的控件层级。 | 左栏只保留稳定的顶层分区；角色编辑内部再用二级页签。主栏用“页面标题→简短说明→设置组”，每组有明确保存反馈。右栏预览仅在编辑角色时出现，并允许收起；诊断信息移到独立页面。 |
| **住房系统** | 房源、角色匹配、推荐、看房、租约、交租、AI 中介、房源管理与小屋布置。 | [Airbnb](https://www.airbnb.com/) 的房源选择模式，以及 [Home Assistant Dashboards](https://www.home-assistant.io/dashboards/) 的管理概览。 | “租房故事”做成分步骤流程：选角色、选房、查看条件、启动；房源用可比较的卡片展示租金/押金/地区/状态。房源管理和中介创作放独立视图。当前大标题与两列选择框占满首屏，行动结果不明显；改版后始终显示当前步骤和下一步。 |
| **商业街** | 像素街景、角色行走、地点互动、自动前往、缩放；实验开关开启时还有场景与行为编辑。 | [Stardew Valley 官方站](https://www.stardewvalley.net/) 作为游戏场景的视觉参照；[VS Code](https://code.visualstudio.com/docs/getstarted/userinterface) 作为编辑模式面板布局参照。 | 玩家模式以画布为主，只常驻角色、地点、交互与必要的缩放。编辑、视差实验、行为树等折叠进“场景工具”，并明确显示当前是玩家模式还是编辑模式。默认窗口至少能看到完整角色脚部及场景底部。 |
| **像素小屋** | 房间风格选择、角色移动/互动、房间布局；实验模式提供家具与行为编辑。 | 同上：游戏场景与创作工具使用不同布局。 | 风格选择做成紧凑的房间切换器；画布占主区域。把维护和编辑按钮放到独立可开关的工具层，避免占掉房间垂直空间；显示清楚当前房间、角色和操作提示。 |
| **商业街日志** | 城市动态、角色行动、交易、社交、公告、天气、当前事件、居民快照和管理入口。 | [GitHub Issues 仪表盘](https://docs.github.com/en/issues/tracking-your-work-with-issues/viewing-all-of-your-issues-and-pull-requests) 的筛选视图/保存视图，以及 [Home Assistant Dashboards](https://www.home-assistant.io/dashboards/) 的状态总览。 | “日志”先给一列可扫描的时间线，筛选与搜索固定在顶部；天气/公告/居民状态做可收起侧栏。空数据时区分“商业街未开启”“暂无记录”“筛选无结果”，并给对应操作。管理页单独处理，不与日志同一层级混排。 |

| 窗口 | 当前功能 | 适合借鉴的方式 | 具体建议 |
| --- | --- | --- | --- |
| **文件夹** | 收纳快捷方式、排序/视图切换、拖出/移入应用。 | [Windows NavigationView](https://learn.microsoft.com/en-us/windows/apps/design/controls/navigationview) 的位置感与工具栏。 | 工具栏仅放当前文件夹可执行的动作；空文件夹提示“把桌面 App 拖入这里”；选中后再显示移动/移除。 |
| **图片** | 截图保存、搜索、排序、列表/网格、详情、下载和删除。 | Windows 文件管理的列表/网格切换模式。 | 图片为空时以“截取桌面”作为主操作；有图片时默认网格缩略图，详情按需打开。当前空白列表占据整窗，截图操作只剩小图标。 |
| **回收站** | 搜索、还原、单项永久删除、清空。 | Windows 文件管理的选择后操作模式。 | 空状态说明如何从桌面删除文件；有选中项后把“还原”放主按钮，永久删除保持危险操作样式。 |
| **文本文档** | 编辑/预览、保存、文本格式、拆分/合并、统计、删除。 | [VS Code 用户界面](https://code.visualstudio.com/docs/getstarted/userinterface) 的编辑区优先和次级命令。 | 编辑区占主要面积；标题/保存状态持续可见；拆分、合并、删除归入次级菜单；未保存内容的离开提示必须明确。 |

## 一套适用于整台模拟电脑的规则

- **外壳一致，内容按任务变化。** 桌面、任务栏、窗口标题、焦点与拖动遵循一套规则；业务 App 不必共用同一个三栏或一套卡片模板。
- **优先给工作内容面积。** 业务 App 首次打开可用更大窗口；模拟浏览器栏应压缩或让用户切换精简模式。商业街/小屋默认应让完整场景可见。
- **统一设计令牌。** 主文字、次文字、边界、焦点、危险/成功、间距、字号、圆角只定义一次。正文建议从 14–16px 起，11–12px 只用于非关键辅助信息；粉蓝保留给品牌和强调，不承担大段正文。
- **主操作每屏一个。** 搜索、发送、保存、开始租房故事、运行查询等操作在各自页面一眼可见。维护、实验和诊断功能通过次级导航或展开面板进入。
- **空状态给路径。** 明确是未创建、未加载、没有匹配还是服务错误；文案后接用户能执行的动作。
- **键盘与状态。** 可见焦点、按钮可辨识标签、加载/成功/失败反馈、禁用原因；按 [WCAG 2.2 Quick Reference](https://www.w3.org/WAI/WCAG22/quickref/) 逐屏核对文字对比和控件可用性。

## 建议的实施顺序与验收

1. **先修底层体验：** 统一令牌、提高社交文字对比、调整业务窗口默认尺寸与可滚动区域。验收：1440×900、1280×720、窄窗口下重要标题、主要操作和内容不互相遮挡。
2. **社交与场景：** 这三屏使用频率高，也最能暴露“内容被装饰淹没”和“画布被工具栏挤掉”的问题。验收：聊天消息/输入一眼可见；街景和小屋首屏能看到角色与可交互区域。
3. **设置、记忆、MCP：** 逐一清理导航，保留现有功能与数据流程。验收：新用户能在不理解后端术语的情况下找到角色设置、记忆来源与联网查询。
4. **住房、日志、系统窗口：** 改善选择、时间线和空状态。验收：任务能从入口完成到结果，不需要通过滚动猜测下一步。

每一步都用项目的隔离测试数据启动本地 Vite，Playwright 无头检查桌面和窄窗口；业务回归沿用现有 E2E。当前文档是研究与改版规格，**尚未修改这些 App 的页面实现**。以上设计结论需在真实含有大量消息、记忆和日志的数据集下再核对密度与滚动表现。
