# 代码质量复查（2026-09-22）

这是修复前的检查快照，文中的行号与“当前流程”描述对应当时版本。后续修复及验证见 [可靠性修复记录](reliability-fixes-2026-09-22.md)。

本轮检查数据可靠性、场景运行与故障定位。没有修改业务代码，没有使用真实用户数据库，也未重新评审密码和用户隔离。以下四项问题有隔离复现依据；第五项是维护性问题。

## 1. 备份恢复缺少失败回滚（优先级高）

位置：[post-system-import.js](../server/features/backup/http/post-system-import.js)，51–115 行。

当前流程先清除记忆索引，再停止后台工作、备份旧库、关闭数据库、覆盖文件、恢复附件并重建索引。旧库备份失败被空 catch 忽略；后续异常只清理临时上传文件并返回 500，没有恢复旧库/附件，也没有恢复已停止的工作状态。

隔离复现：执行真实路由处理函数，以内存替身代替全部文件操作。让旧库备份和新库复制失败，观测顺序为：清索引 → 停调度器 → 停工作线程 → 备份失败 → 关闭旧库 → 复制失败 → 清理临时文件。响应 500，缓存中的旧数据库已移除，未执行恢复动作。不同失败位置的后果不同；此复现没有断言真实文件已经丢失。

建议先在临时位置完整校验导入数据库和附件，保证旧数据备份成功后再切换；任何切换失败都要恢复原数据库、附件和运行服务。数据库已恢复但搜索索引重建失败时，应明确报告可重试的索引状态。

## 2. 场景保存允许旧状态覆盖新状态（优先级高）

位置：[behaviorTreeRepository.js](../server/features/city/behaviorTreeRepository.js)，22–49 行；[CommercialStreetScene.jsx](../client/src/features/city/scene/CommercialStreetScene.jsx)，692–774 行；[RoomScene.jsx](../client/src/features/city/scene/RoomScene.jsx)，727–814 行。

后端按 scene_key 无条件替换完整树。前端轮询比较内容签名，但没有服务端修订号校验、并发写入冲突处理或防止旧响应被应用的请求序号。HTTP 保存失败也没有明确的“尚未同步”界面状态。

隔离复现：在内存 SQLite 上调用真实 repository，先保存 version=20，再模拟迟到请求保存 version=10；最终读取到 version=10。请求顺序决定结果，旧写入不会被拒绝。同一账号开多个窗口或网络响应顺序变化时会触发此类覆盖，与不同用户数据库隔离是两个问题。

建议增加独立的服务端 revision 与条件写入；不要只依赖客户端树内的 version，因为重建/重置可能有不同的版本语义。客户端需要串行保存或合并待保存状态、忽略过期响应，并展示同步失败和冲突。

## 3. 移动按键没有限定到当前场景（优先级中）

位置：[RoomScene.jsx](../client/src/features/city/scene/RoomScene.jsx)，1010–1023 行；[CommercialStreetScene.jsx](../client/src/features/city/scene/CommercialStreetScene.jsx)，3127–3146 行；后台窗口由 [ApplicationView.jsx](../client/src/app/ApplicationView.jsx) 保留挂载。

两个场景都在 window 注册键盘监听，只排除输入框，没有判断场景焦点或前台窗口。移动键集合也没有在窗口失焦时统一清空。

无头浏览器复现：打开小屋，将键盘焦点移到场景外的“社交”桌面按钮，再按移动键，小屋人物仍移动。随后打开商业街，页面中观测到四个挂载的场景实例；把焦点放在前台商业街画布，按 D，四个实例的人物坐标都发生变化。这证明后台场景也接收了同一输入；四个实例的产生原因尚未单独追踪。

建议由桌面窗口显式传入是否处于前台，并让键盘输入只作用于获得焦点的场景；失焦/切窗时清空按键状态。另排查场景实例生命周期，避免重复运行无必要的监听器与动画循环。

## 4. 数据库升级会吞掉真实错误（优先级中）

位置：[characters/migrations/legacy.js](../server/features/characters/migrations/legacy.js)，2–17 行；同类写法在其他历史 migration 中也存在。

这些 catch 原意是忽略“列已存在”，实际却忽略所有异常。隔离调用 upgrade1，将三个 ALTER TABLE 都设为抛出 SQLITE_IOERR，函数仍正常返回，未报告任何错误。这会使数据库升级失败延迟到后续业务查询才暴露。

建议逐步使用现有 addColumnIfMissing 辅助方法和有版本记录的迁移；真正的 I/O、只读或损坏错误应阻止启动，并记录迁移步骤与异常。不要为了整理结构改变历史迁移顺序。

## 5. 功能目录已分开，运行组件仍承担过多职责

当前 CommercialStreetScene.jsx 为 3953 行，RoomScene.jsx 为 2628 行；同时持有画布状态、移动/碰撞、行为执行、网络同步、存储及工具装配。单看行数并不能判定代码有错，但上述职责共用大量状态和 ref，修复同步或移动时难以确认影响范围。

建议先修复前四项，再按输入与移动、行为执行、同步与持久化提取独立模块，补上可控制网络响应顺序、窗口焦点和失败恢复的测试。避免只把长文件分成含糊的 operations/callbacks 文件而保留全部交叉依赖。
