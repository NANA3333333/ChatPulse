# 结构复查后的可靠性修复（2026-09-22）

对应 [四项缺陷的检查记录](structure-bug-audit-2026-09-22.md)。本轮完成缺陷修复和回归用例，没有继续扩大到主界面、城市运行时的大规模结构拆分。

## 场景恢复记录

实现：`client/src/features/city/scene/behaviorRecoveryStore.js`、`useBehaviorTreeSync.js`。

- 每个同步实例使用独立的本地持久化记录，保存确认不会无条件删除同场景的公共恢复键。
- 每个标签页另存一份独立的会话恢复数据，刷新后恢复本页修改；浏览器复制标签页后，其中一页放弃修改不会使另一页的修改丢失。
- 写入记录带唯一版本标识，恢复来源有新编辑时不清除它；重试、组件重新挂载和旧格式恢复记录迁移均有测试。
- 用户明确加载服务器版本前，保留独立备份。服务端 revision 冲突检查继续生效，过期本地版本不会静默覆盖服务器。

## 转账、退款与红包

实现：`server/features/economy/repository.js`。

- 已领取转账退款前检查收款方余额，不足时返回失败，不改变转账状态及任何余额。
- 创建转账、领取、退款各自在 SQLite 事务内执行，状态检查、账目记录、双方余额更新共同提交；任何一步写入异常都会回滚。
- 红包发送和领取存在同样的多步写入，因此也采用事务保护。
- 故障测试覆盖记录插入失败、入账失败、退款扣回失败，以及失败后的重试。正常退款、重复退款、权限限制和余额守恒也有覆盖。

本轮不根据不完整的旧记录自动重算历史余额；修复保证后续这些操作的一致性。

## 角色导入与计时器

实现：`server/features/backup/characterImportService.js`、对应 HTTP 路由，以及 `server/features/private-chat/scheduling.js` / `runtime.js`。

- 存档导入服务统一管理事务和调度的暂停、恢复。
- 导入失败时，恢复原来的执行时间和主动/自定时类型；成功时，按导入后的角色设置重新安排。
- 关闭主动消息、非活跃、已屏蔽角色以及关闭后台自动运行的环境不会因导入而启动主动消息。
- 索引重建失败仍返回明确警告，已提交的导入不会被误当成数据库回滚，调度会恢复。
- 正在处理聊天时导入返回 409；同一角色重复暂停会被拒绝。服务关闭后，仍在完成中的导入也不能重新启动旧计时器。
