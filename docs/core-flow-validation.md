# 核心业务回归记录（2026-09-17）

本轮在功能拆分之后，检查角色、私聊、群聊、个人资料和记忆导入的保存、失败恢复、刷新与服务重启行为。使用临时数据库、测试账号和无头 Chromium，没有操作实际账号数据。

## 修复结果

| 场景 | 问题与修复 |
| --- | --- |
| 空账号首次打开社交 | 原先用角色数量判断是否加载完成，空列表会一直显示加载状态。现在单独记录加载完成，并在社交窗口提供创建群聊入口。 |
| 创建角色、创建群聊 | 统一校验 HTTP 和业务错误，失败保留输入并显示原因；提交期间加锁。角色创建重试复用同一 ID。 |
| 个人资料、角色资料保存 | 保存失败不关闭编辑；保存期间新输入的内容不被旧请求清除。 |
| 群消息发送 | 每个群独立保存草稿和历史；HTTP 成功即显示已保存消息，与 WebSocket 回显去重；失败保留草稿。切换群聊取消过时的历史请求，重连补取消息。 |
| 群消息定位 | 搜索上下文与最新历史请求互斥，避免迟到的历史覆盖搜索结果；切换群聊时取消追加历史请求。 |
| 群管理 | 改名、成员管理、AI 设置、清空和解散校验服务端结果后再更新界面；失败保留当前界面并显示错误，避免失败后误刷新。 |
| 群消息落库后异常 | 通知或 AI 调度准备失败时仍返回已保存消息及警告，避免把已保存消息报告为发送失败。空白或非文本消息返回 400。 |
| 旧格式记忆替换导入 | 全部准备完成后在一个 SQLite 事务中替换；任一写入失败回滚旧记录。混有无效条目的替换请求直接拒绝；合并模式仍可跳过无效条目。索引操作在提交后进行，异常作为警告返回。 |

## 复跑

Windows 使用仓库 Node 20，以匹配 SQLite 原生模块。开发服务器由 E2E 运行器在临时端口启动，结束后清理进程和临时数据库。

```powershell
# 仓库根目录
.\.runtime\node20\node.exe scripts/check-architecture.cjs
.\.runtime\node20\node.exe tests/e2e/run.cjs

# 仅跑空数据库的核心页面流程，或设为 group 仅跑群聊
$env:CHATPULSE_E2E_SUITE = 'core'
.\.runtime\node20\node.exe tests/e2e/run.cjs
Remove-Item Env:CHATPULSE_E2E_SUITE

# server 目录
..\.runtime\node20\node.exe --test

# client 目录
..\.runtime\node20\node.exe node_modules/eslint/bin/eslint.js . --max-warnings 0
..\.runtime\node20\node.exe node_modules/vite/bin/vite.js build --outDir ../.codex_tmp/core-flow-audit/client-dist
```
