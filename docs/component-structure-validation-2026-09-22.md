# 页面内部职责拆分（2026-09-22）

本轮继续拆分设置、记忆库、群聊内部的独立职责。功能目录保持不变，页面入口组合状态与视图，具体操作有明确的查找位置。

## 已完成

| 功能 | 拆分后的职责 |
| --- | --- |
| 设置 | 人格、模型、行为、声音、角色数据、个人资料、登录会话、备份、诊断侧栏分别作为组件；角色草稿、个人资料、模型列表、会话管理、备份请求分别由专用 hook 管理。 |

| 群聊与红包 | 群管理独立为 GroupManageDrawer；主动消息档位独立配置；红包弹窗、红包卡片和金额格式化归入 economy。群聊窗口通过导入调用这些组件。 |

设置页已清除无法从现有导航进入的旧角色弹窗、旧模型总览和旧设置总览，以及相应的无用状态和回调。记忆库未使用的旧列表渲染也已移除。各分区保留原来的样式类、字段与接口协议。

设置入口从 3528 行缩减为约 1100 行，记忆库入口从 3095 行缩减为约 1500 行。新拆出的代码已统一格式；行数仅用于说明入口职责的变化，不作为继续拆分的唯一依据。

## 查错入口

- [设置页逐项导航](features/settings.md)：例如“角色模型保存失败”沿 CharacterModelSettings → useCharacterConfiguration → characters 接口查找。
- [记忆库](features/memory.md)：导入看 useExternalMemoryImport；任务进度看 useMemoryMaintenance；编辑、删除和追溯看 useMemoryEditing。
- [群聊](features/group-chat.md)：设置看 GroupManageDrawer；历史与草稿看 useGroupMessages。
- [红包与转账](features/economy.md)：红包组件集中在 economy/components。

应用入口不再从群消息窗口获取群管理组件，直接加载其独立模块。结构检查新增前端 JSX 扩展名检查，防止把视图抽到普通 `.js` 文件后直到构建阶段才报错。
