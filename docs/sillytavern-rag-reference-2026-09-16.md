## 3. 正常召回路径仅传索引，分离辅助模型的推演

辅助模型依据近期对话与总结大纲选取索引，例如 `<recall>AM01,AM02</recall>`。本机配置 `extractTags=recall`，源码 6321–6367 行提取最后一组该标签；总结表行以编码为关键词触发世界书条目（9158–9190 行）。

因此正常路径传给正文的是最终注入提示与召回索引，再由世界书提供对应历史内容，而不是完整的辅助推演、候选剧情和打分说明。

边界：如果没有找到指定标签，代码仍保留完整辅助回复作为回退。这不是绝对保证辅助推演永不进入正文输入。

这套主要是模型选择表格索引的召回，不宜直接等同于向量检索。

## 4. “去重”不等于正文语义防复述

检查到的相关机制包括：

- 规划提示要求合并索引、去重和排序；对应同一轮重复选中同一条记忆。
- 总结世界书条目设置 `prevent_recursion=true`；用于避免条目继续触发其他条目的递归召回。
- 生成事件有去重锁；防止同一次发送被多个钩子重复处理。
- 同一张表的行和包裹有固定的分组顺序，避免重复/交错注入顺序。

这些都不能直接证明主模型不会换词复述用户的话或重讲旧事。在核对的召回注入提示与包裹中，没有发现专门禁止正文语义复述的完整规则。

当前规划提示还要求合并后召回 18–22 条（库存不足时按库存），并为多种候选剧情寻找记忆。这适用于其小说玩法；不能当作短消息私聊的推荐默认值。

## 对 ChatPulse 的参考结论

最值得借鉴的是让模型明确识别“本轮输入”“当前状态”“过去对话记录”三类内容，以及让辅助模型的检索推演和正文输入分离。

用户提出的定位更精确：召回内容是过去对话的概况，只作为对话参考；它能提示当时聊过什么，不能自动证明当时的每项说法都正确，也不能证明情况延续至今或本轮必须重提。

调查完成后，用户授权按这一定位修改。ChatPulse 已在 v4 提示中清理普通生成的 `reference facts`、`factual recall anchors` 等事实化表述，并分隔过去对话参考与本轮输入；实现及验证范围见 [私聊文风记录](private-reply-style-presets.md)。这不表示已经通过生成对照证明本插件或新提示能稳定防止复述。
