# 可靠性修复与回归（2026-09-22）

对应 [代码质量复查](code-quality-audit-2026-09-22.md) 的前四项。测试使用临时数据库与模拟模型，不读取或替换真实用户数据。

## 备份恢复

- HTTP 入口只处理上传、解包和响应；恢复流程归 [restoreService.js](../server/features/backup/restoreService.js)。
- 先在临时目录校验 SQLite 完整性及必要表，准备旧附件副本，再暂停工作、备份旧库并切换。旧库备份失败立即中止。
- 切换、附件复制或新库初始化失败时，恢复原数据库和被覆盖的附件，重新打开旧库并恢复工作。导入不再预先清空搜索索引，也不删除归档未覆盖的附件。
- 如果磁盘持续故障导致回滚也失败，保留数据库旁的 `.restore-*` 恢复目录并记录路径；该账号保持维护状态，防止后续请求误建空库。处理时先停服务、从恢复目录恢复数据库和附件，再重启，不能只重启绕过维护状态。
- 数据恢复成功后才重建索引。索引或工作重启失败通过响应 `warnings` 返回，设置页会明确提示，不把已完成的数据恢复误报为失败。
- 正在回复、存在已登记的后台任务或重复恢复时返回 409；切换期间新的数据库访问返回 503。这是当前单进程内的维护保护，不是跨进程锁，也未覆盖所有已经持有数据库引用的异步工作。进程被强制终止后的自动恢复仍不在本轮实现范围内。

## 场景同步

- [behaviorTreeRepository.js](../server/features/city/behaviorTreeRepository.js) 使用独立的服务端 `revision`，SQLite 事务内比较并更新；树自身的 `version` 仍用于行为格式，可重新生成或重置。
- GET 返回 `revision`；POST 必须带 `expected_revision`，缺少时返回 428，冲突时返回 409 和当前修订号。相同树的重试不会重复增加修订号。已有表自动补列，保留历史行。
- 客户端保存串行执行，保留最新待保存树；过期读取不能覆盖本地修改。同步状态机归 [behaviorSyncClient.js](../client/src/features/city/scene/behaviorSyncClient.js)，React、网络与浏览器存储连接归 [useBehaviorTreeSync.js](../client/src/features/city/scene/useBehaviorTreeSync.js)。
- 失败或冲突时工具栏提示；网络失败可重试，冲突可选择加载服务器版本。未同步树存于原存储键后缀 `.pending-sync`，显式加载服务器版本前另存 `.unsynced-backup`。浏览器禁止存储或空间不足时仅保证当前页面的内存副本。
- 服务器轮询在生成、玩家互动期间暂停应用；卸载后取消请求。前后端需一起更新，旧客户端不带修订号的保存会被拒绝。

## 场景输入与数据库升级

- 桌面向场景传入 `isActive`；[sceneKeyboard.js](../client/src/features/city/scene/sceneKeyboard.js) 只让前台且画布获得焦点的场景接收移动键，焦点离开、窗口失焦或页面隐藏时清空按键。后台场景的全部动画生命周期尚未重构。
- 历史 migration 仅忽略已确认的重复列错误，其余 SQLite I/O、只读、损坏和忙碌错误继续向上抛出。已经移除的旧列先检查再读取/删除，保留原执行顺序。初始化失败关闭数据库句柄，已认证请求遇到数据库故障返回服务错误，不再误报登录失效。
- 未引入迁移版本账本；后续新增迁移仍应逐步采用明确的列检查和版本管理。
